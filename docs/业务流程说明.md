# 业务流程说明

## 1. 用户注册登录流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant F as 前端
    participant B as 后端
    participant DB as MySQL

    U->>F: 输入邮箱/手机号和密码
    F->>B: POST /auth/register 或 /auth/login
    B->>DB: 查询或创建用户
    DB-->>B: 用户信息
    B-->>F: JWT token + 用户信息
    F->>F: 保存 token 到 localStorage
```

## 2. 发起问答流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant F as 前端
    participant B as FastAPI
    participant DB as MySQL
    participant V as Qdrant
    participant L as LLM

    U->>F: 输入问题并点击发送
    F->>B: POST /chat/stream
    B->>DB: 校验每日提问次数
    B->>B: 本地业务意图分类
    B->>DB: 保存用户消息
    B-->>F: SSE session 事件
    B-->>F: SSE progress: 正在识别问题类型
    B->>L: 判断是否需要知识库
    B-->>F: SSE progress: 正在改写检索问题
    B->>L: 改写多个检索 query
    B-->>F: SSE progress: 正在检索知识库
    B->>V: Hybrid 检索
    B-->>F: SSE progress: 正在筛选相关资料
    B->>B: RRF 融合 + Rerank + 过滤
    B-->>F: SSE progress: 正在生成回答
    B->>L: 拼接 Prompt 调用模型
    L-->>B: 流式 token
    B-->>F: SSE message 增量事件
    B->>DB: 保存 AI 回复和引用来源
    B-->>F: SSE saved 事件
```

业务意图分类使用本地关键词规则，优先级为：投诉 > 售后问题 > 产品咨询 > 闲聊 > 其他。包含明显负面情绪的产品表达会优先标记为投诉。

问答过程中的 `progress` 事件只用于前端当前气泡展示，不保存到数据库；模型首个 token 到达后，进度文案会被正式回答替换。

## 3. 知识库上传流程

知识库为企业共享数据，登录用户只用于鉴权，不作为文档归属条件。

启动初始化开启时，FastAPI lifespan 会先创建 MySQL 数据库和表，再按同一套知识库导入逻辑扫描 `testdocs` 目录；已存在的同内容文档会按 `file_hash` 跳过。

```mermaid
flowchart TD
    A["上传 .txt/.md 文档"] --> A1["前端立即显示处理中"]
    A1 --> B["读取文件并计算 sha256"]
    B --> B1{"file_hash 是否已存在"}
    B1 -->|就绪/处理中| B2["返回重复文档提示"]
    B1 -->|失败| B3["复用失败记录重新处理"]
    B1 -->|不存在| B4["创建新文档记录"]
    B3 --> C["knowledge_documents 状态=处理中"]
    B4 --> C["knowledge_documents 状态=处理中"]
    C --> D["解析文本并清洗"]
    D --> E{"是否识别为 QA 文档"}
    E -->|是| F1["一问一答一个 chunk"]
    E -->|否| F2["普通递归文本切分"]
    F1 --> F["写入 knowledge_chunks"]
    F2 --> F["写入 knowledge_chunks"]
    F --> G["调用 Embedding"]
    G --> H["写入 Qdrant"]
    H --> I["状态=就绪"]
    G -->|失败| J["清理向量并状态=失败"]
```

## 4. 知识库删除流程

删除知识库文档会影响所有用户可见和可检索的企业知识库。

```mermaid
flowchart TD
    A["用户删除文档"] --> B["校验文档是否存在"]
    B --> C["删除 Qdrant 向量"]
    C --> D["删除 MySQL knowledge_chunks"]
    D --> E["删除 knowledge_documents"]
```

## 5. 会话删除流程

```mermaid
flowchart TD
    A["用户删除会话"] --> B["校验会话归属"]
    B --> C["查询会话下所有 message_id"]
    C --> D["删除 message_sources"]
    D --> E["删除 feedbacks"]
    E --> F["删除 chat_messages"]
    F --> G["删除 chat_sessions"]
```

每日提问次数不会因为删除会话而减少。

## 6. 反馈流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant F as 前端
    participant B as 后端
    participant DB as MySQL

    U->>F: 点击点赞或踩
    F->>B: POST /feedback
    B->>DB: 校验 AI 消息归属
    B->>DB: 新增或更新反馈
    B-->>F: 返回反馈结果
```

## 7. 异常处理流程

| 场景 | 处理方式 |
|---|---|
| LLM 认证失败、限流、超时 | 后端写日志，前端展示友好提示 |
| Embedding 失败 | 文档状态改为失败，清理已写入向量 |
| Qdrant 检索失败 | 后端日志记录，返回兜底回答 |
| 超过每日次数 | 拒绝发送，前端禁用输入框和发送按钮 |
| 文档无内容 | 文档状态改为失败并保存错误信息 |
