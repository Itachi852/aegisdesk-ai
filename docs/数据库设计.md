# 数据库设计

数据库使用 MySQL，主要存储用户、会话、消息、企业共享知识库元数据、反馈、引用来源和每日提问次数。向量数据存储在 Qdrant，MySQL 中只保存知识块文本和元数据。

## ER 图

```mermaid
erDiagram
    users ||--o{ chat_sessions : owns
    chat_sessions ||--o{ chat_messages : contains
    chat_messages ||--o{ feedbacks : receives
    chat_messages ||--o{ message_sources : cites
    knowledge_documents ||--o{ knowledge_chunks : splits
    users ||--o{ user_daily_question_usages : has

    users {
      bigint id PK
      varchar email
      varchar phone
      varchar password_hash
      timestamp created_at
    }

    chat_sessions {
      bigint id PK
      bigint user_id
      varchar title
      timestamp created_at
      timestamp updated_at
    }

    chat_messages {
      bigint id PK
      bigint session_id
      varchar role
      text content
      varchar intent
      timestamp created_at
    }

    knowledge_documents {
      bigint id PK
      varchar name
      varchar file_type
      varchar file_hash
      varchar status
      text error_message
      timestamp created_at
    }

    knowledge_chunks {
      bigint id PK
      bigint document_id
      varchar vector_id
      text content
      varchar summary
      timestamp created_at
    }

    message_sources {
      bigint id PK
      bigint message_id
      bigint document_id
      bigint chunk_id
      decimal score
      varchar doc_name
      varchar summary
    }

    feedbacks {
      bigint id PK
      bigint message_id
      bigint user_id
      varchar rating
      text comment
      timestamp created_at
    }

    user_daily_question_usages {
      bigint id PK
      bigint user_id
      date usage_date
      int question_count
      timestamp created_at
      timestamp updated_at
    }
```

## 表结构说明

### users

保存用户账号和密码哈希。

| 字段              | 说明     |
| --------------- | ------ |
| `id`            | 用户 ID  |
| `email`         | 邮箱，唯一  |
| `phone`         | 手机号，唯一 |
| `password_hash` | 加密后的密码 |
| `created_at`    | 注册时间   |

### chat_sessions

每次独立对话对应一个 session。

| 字段           | 说明                 |
| ------------ | ------------------ |
| `id`         | 会话 ID              |
| `user_id`    | 所属用户               |
| `title`      | 会话标题，默认取首条问题前 30 字 |
| `created_at` | 创建时间               |
| `updated_at` | 最后一次对话时间           |

### chat_messages

保存用户消息和 AI 回复。

聊天生成过程中的“正在识别问题类型、正在检索知识库”等阶段提示只通过 SSE 临时推送给前端，不写入 `chat_messages`。

| 字段           | 说明                   |
| ------------ | -------------------- |
| `id`         | 消息 ID                |
| `session_id` | 所属会话                 |
| `role`       | `user` 或 `assistant` |
| `content`    | 消息内容                 |
| `intent`     | 用户消息的业务意图分类          |
| `created_at` | 创建时间                 |

业务意图枚举：

| 存储值                    | 展示文案 |
| ---------------------- | ---- |
| `product_consultation` | 产品咨询 |
| `after_sales`          | 售后问题 |
| `chat`                 | 闲聊   |
| `complaint`            | 投诉   |
| `other`                | 其他   |

### knowledge_documents

保存知识库文档元数据。

| 字段              | 说明                      |
| --------------- | ----------------------- |
| `id`            | 文档 ID                   |
| `name`          | 文件名                     |
| `file_type`     | 文件类型                    |
| `file_hash`     | 文件内容 sha256，用于识别重复文档，唯一 |
| `status`        | `处理中`、`就绪`、`失败`         |
| `error_message` | 失败原因                    |
| `created_at`    | 上传时间                    |

知识库按文件内容 hash 去重，不按文件名去重：同样内容已存在且状态为 `就绪` 时拒绝重复上传；同名但内容不同允许作为新文档上传。

### knowledge_chunks

保存文档切片文本。

| 字段            | 说明                            |
| ------------- | ----------------------------- |
| `id`          | chunk ID，同时作为 Qdrant point id |
| `document_id` | 所属文档                          |
| `vector_id`   | 向量 ID                         |
| `content`     | 切片原文                          |
| `summary`     | 切片摘要                          |
| `created_at`  | 创建时间                          |

QA 文档不会新增表字段；系统会在切分阶段把每组问答保存为一条 `knowledge_chunks` 记录，普通文档仍按通用文本 chunk 保存。

上传时前端展示的“处理中”临时行只用于页面反馈；数据库仍以 `knowledge_documents.status` 字段保存真实处理状态。

### message_sources

保存 AI 回答引用了哪些知识片段。

| 字段            | 说明       |
| ------------- | -------- |
| `message_id`  | AI 消息 ID |
| `document_id` | 文档 ID    |
| `chunk_id`    | chunk ID |
| `score`       | 相关性分数    |
| `doc_name`    | 文档名快照    |
| `summary`     | 片段摘要     |

### feedbacks

保存用户对 AI 回答的点赞或踩。

| 字段           | 说明                 |
| ------------ | ------------------ |
| `message_id` | AI 消息 ID           |
| `user_id`    | 用户 ID              |
| `rating`     | `like` 或 `dislike` |
| `comment`    | 可选文字反馈             |

### user_daily_question_usages

独立记录每日提问次数，避免用户删除会话后绕过限制。

| 字段               | 说明      |
| ---------------- | ------- |
| `user_id`        | 用户 ID   |
| `usage_date`     | 日期      |
| `question_count` | 当日已提问次数 |

唯一约束：

```text
(user_id, usage_date)
```

## 设计说明

- 删除会话时同步删除消息、引用来源和反馈。
- 删除知识库文档时同步删除 MySQL chunk 和 Qdrant 向量。
- 知识库是企业共享数据，不按用户隔离；会话、反馈和每日提问次数仍按用户隔离。
- 每日提问次数不依赖 `chat_messages`，因此不会被删除会话影响。
- `message_sources` 保存文档名快照，避免文档删除后历史回答引用显示为空。
